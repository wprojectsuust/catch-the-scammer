# Лаборатория «Поймай мошенника»

## Локальный MVP

Из каталога репозитория с Python 3.14:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
DATA_DIR=../../work/hackathon/data
python -m antifraud train --data-dir "$DATA_DIR" --model models/mvp-001
python -m antifraud sandbox --model models/mvp-001 --output runtime/sandbox.json
python -m unittest discover -v
python -m antifraud serve --model models/mvp-001 --data-dir "$DATA_DIR"
```

Откройте [локальное приложение](http://127.0.0.1:8000/). Кнопка «Данные хакатона» использует каталог, указанный в `--data-dir`. Через форму можно загрузить собственные `clients.csv`, `transactions_history.csv` и `transactions_test.csv`. Если модель в `models/mvp-001` уже обучена и код признаков совпадает, начните с запуска песочницы или сервера. После изменения признаков обучите модель в новом каталоге.

Пакетный анализ с тем же сценарием приложения:

```bash
python -m antifraud analyze --data-dir "$DATA_DIR" --model models/mvp-001 --output runtime/scored.csv
```

Порог по умолчанию выбран на сентябрьской валидации под лимит ложных тревог 0,5%. Интерфейс показывает влияние порога на число операций в очереди. Доля ложных тревог вычисляется отдельно на размеченной истории. Файл экспорта содержит оценку подозрительности, категорию и объяснение для каждой операции.

[План и архитектура](docs/implementation-plan.md) · [Результаты проверки MVP](docs/research/mvp-validation.md)


Три модели оценивают подозрительность операции. Скрипт сравнивает их на известных исторических метках по одному временному протоколу. Результаты первого прогона в [results.json](results.json).

## Запуск

Из каталога лаборатории, с Python 3.14 и распакованными материалами хакатона:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_lab.py --data-dir ../../work/hackathon/data --output results.json
python -m unittest -v
```

Аргументу `--data-dir` можно передать любой каталог с исходными `clients.csv` и `transactions_history.csv`. Граф строится из исполненных переводов истории. Скрипт сохраняет только агрегированные метрики и параметры.

## Протокол

| Период | Назначение | Размечено | Мошенничество |
| --- | --- | ---: | ---: |
| Август | Обучение CatBoost и графового классификатора | 9 660 | 202 |
| Сентябрь | Выбор из трёх конфигураций на модель и настройка порогов | 9 106 | 187 |
| 1–15 октября | Итоговая проверка зафиксированных моделей и порогов | 4 642 | 100 |

Конфигурации сравниваются по average precision (AP). Для каждой модели на сентябре выбираются пороги, которые дают максимальную полноту при доле ложных тревог до 0,5%, 1% и 2% среди подтверждённо законных операций. При одинаковой полноте берётся более строгий порог. Порог переносится на октябрь без корректировки.

Обучение и метрики используют операции с подтверждённой меткой. Операции с неизвестной меткой пополняют прошлую историю. Модели получают хронологические признаки и видят метки только за август и сентябрь. Текущая операция и операции той же секунды добавляются в историю после расчёта признаков для всей секунды. Тесты проверяют это на контролируемом примере и проверяют, что удаление октября сохраняет признаки августа и сентября. Финальный файл новых операций без меток в эксперименте не используется.

- **Табличная модель.** Неглубокий CatBoost с L2-регуляризацией. Использует сумму, долю остатка, время суток, регион, тип операции, параметры клиента и признаки его поведения. Историческая аномалия суммы считается через медиану и MAD логарифмов сумм клиента, начиная с пяти прошлых наблюдений.
- **Графовая модель.** L2-логистическая регрессия на 30 признаках направленного временного графа. Среди них степени счетов, повторяющиеся и обратные связи, пути в два шага, потоки за час и сутки. Граф включает исполненные переводы с более ранним временем. Текущий статус исполнения не используется как предиктор.
- **Математическая модель.** Сумма ограниченных вкладов с неотрицательными весами. Учитывает сумму, долю остатка, интенсивность, новизну, регион и совместный эффект крупной суммы и нового устройства. Функция `contributions` возвращает вклад каждого слагаемого.

## Первый результат

Основное сравнение использует флаги новизны, вычисленные по доступной прошлой истории. Дополнительный прогон использует флаги организаторов.

| Модель | AP август | AP сентябрь | AP октябрь | Найдено из 100 в октябре | Ложные тревоги в октябре |
| --- | ---: | ---: | ---: | ---: | ---: |
| CatBoost | 0,795 | 0,676 | 0,721 | 75 | 65 (1,43%) |
| Математический скоринг | 0,439 | 0,530 | 0,541 | 73 | 101 (2,22%) |
| Временной граф | 0,031 | 0,028 | 0,039 | 0 | 0 |

Показатели тревог приведены для порогов, выбранных под лимит 1% в сентябре. У графовой модели ни один порог в пределах этого лимита не дал верных срабатываний на сентябре, поэтому был выбран вариант без предупреждений. При лимите 2% на сентябре граф нашёл в октябре 5 из 100 случаев и дал 141 ложную тревогу. AP случайного ранжирования на октябре ориентировочно соответствует доле положительных меток, 0,022.

С готовыми флагами организаторов октябрьский AP CatBoost составил 0,724, а математического скоринга 0,541. У CatBoost AP на обучении выше, чем на сентябрьской и октябрьской выборках. При этом от сентября к октябрю AP вырос, а фактическая доля ложных тревог превысила сентябрьский лимит. Качество измерено на одном отложенном периоде и среди размеченных операций. В архиве нет дат подтверждения меток и истории изменения анкеты, поэтому лаборатория предполагает доступность августовских меток при обучении и доступность справочных полей клиента в момент операции. Слабый результат самостоятельной графовой модели оставляет открытым вопрос о пользе графовых признаков в CatBoost.

[ADR 0001 об отказе от графового скоринга в MVP](docs/adr/0001-defer-graph-scoring.md)

## Роли моделей и проверка устойчивости

В MVP очередь проверок формирует CatBoost. Математический скоринг используется для сравнения и демонстрации метода на презентации.

```bash
python backtest.py --data-dir ../../work/hackathon/data --output backtest-results.json
python -m unittest -v
```

В каждом из трёх окон обе модели заново выбирают конфигурацию и пороги по предшествующему периоду. Итоговые окна не пересекаются. Для октябрьского окна сохранён исходный протокол. Во всех окнах флаги новизны рассчитываются по прошлым операциям.

| Итоговое окно | AP CatBoost на обучении | AP CatBoost на проверке | AP матмодели на проверке | Найдено CatBoost при строгом пороге | Доля ложных тревог CatBoost |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1–15 сентября | 0,699 | 0,574 | 0,551 | 40 из 96 | 0,36% |
| 16–30 сентября | 0,795 | 0,683 | 0,514 | 52 из 91 | 0,40% |
| 1–15 октября | 0,795 | 0,721 | 0,541 | 68 из 100 | 0,70% |

Строгий порог выбирался в каждом окне под лимит 0,5% ложных тревог на валидации. При лимите 1% на валидации фактическая доля на проверке составила 0,57%, 1,11% и 1,43%. Разрыв AP между обучением и проверкой составил от 0,074 до 0,126. Автотесты проверяют временные границы, изоляцию отложенных меток, неизменность настройки моделей при подмене этих меток, построение признаков и выбор порога при совпадающих баллах.

Проверка ретроспективная. Периоды взяты из одной выгрузки, и одна и та же операция может быть итоговой для раннего окна и использоваться в более позднем окне. Результаты оценивают будущие операции в этой выгрузке. Для оценки на новых клиентах или на новом периоде с подтверждёнными метками нужны отдельные данные.
