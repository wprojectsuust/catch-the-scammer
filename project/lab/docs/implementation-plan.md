# План MVP и лаборатории

Принят 7 ноября 2026 года.

## Продукт

Основной скоринг выполняет CatBoost. Математическая модель остаётся исследовательским методом и частью презентации. Продукт использует авторские причинные признаки поведения, рассчитанные по прошлым операциям клиента.

Первый MVP предоставляет загрузку CSV, ранжированную очередь проверок, карточку операции с вкладом признаков CatBoost, историю клиента, временное воспроизведение операций, изменение порога, экспорт результатов и сведения о качестве входных данных. Риск показывается как оценка подозрительности. Метрики качества вычисляются на известных метках.

## Последовательность

1. Сохранить исходные исследования, результаты и ADR в Git.
2. Собрать доменные типы, сценарий анализа, адаптеры CSV, признаков и CatBoost, CLI обучения и скоринга.
3. Создать лабораторию-песочницу с семью сценариями ТЗ. Проверить корректность обработки данных, временную причинность, объяснения и сохранённую модель.
4. Интегрировать проверенный сценарий анализа в браузерный интерфейс.
5. Выполнить сквозной прогон на данных хакатона, зафиксировать результаты проверки и коммиты.

## Архитектура

Домен содержит операции, клиентов, оценки риска и объяснения. Сценарии приложения зависят от домена и портов подготовки признаков и скоринга. Адаптеры реализуют CSV, pandas и CatBoost. Интерфейсы CLI и HTTP создают адаптеры и вызывают сценарии приложения.

Зависимости направлены внутрь. Модель и обработка CSV доступны через порты. UI и песочница используют одинаковый сценарий анализа. Результат анализа получает отдельный ID и хранится как снимок, чтобы параллельные запросы не смешивали данные.

## Эффективность

Модель загружается один раз на процесс. Признаки строятся в хронологическом порядке. Повторное изменение порога фильтрует уже рассчитанные результаты. История клиента индексируется по счёту. Для интерфейса используются страницы результатов. Размер загрузок и число сохранённых анализов ограничены.

## Проверки

Автотесты охватывают валидацию CSV, пропуски, дубликаты, границы временных окон, изоляцию итоговых меток, одинаковые временные отметки, загрузку модели, объяснения и HTTP-сценарии. Синтетические сценарии проверяют механизм и показывают поведение модели. Для измерения качества используются размеченные исторические данные.

Изменения модели проходят лабораторию и временной backtest перед включением в продукт. Гипотеза, протокол, результаты и решение фиксируются в docs/research. Уже просмотренные периоды считаются ретроспективной проверкой. Для независимого подтверждения требуется новый размеченный набор.
